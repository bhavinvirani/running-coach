# Shared contracts (packages/shared)

- `src/contracts/<resource>.ts`: zod schemas for every API request and response and every message between the API and the Garmin service (its errors use `garminProblemSchema`, `problemSchema` plus an optional `tokenBundle` that never reaches the browser), exported with inferred types (`export type MeResponse = z.infer<typeof meResponseSchema>`) and from `src/index.ts`. Nothing else in the repo declares these shapes.
- `src/error-codes.ts`: the single list of error codes as a `const` object. Adding a code adds its user-facing message to `apps/web/src/lib/errors.ts` in the same PR.
- `src/units.ts`: SI storage units and pure conversions (m to km or mi, s to pace, bpm); no locale formatting here.
- `src/json-schema/` is generated by `pnpm contract:build` and committed; `pnpm check` fails on drift. The Python service's `tests/test_contract.py` validates every response it builds from its fixtures against it.
- Imports in `src/`: `zod` only. No I/O, React or `node:` modules. Response schemas use `.strict()`, so the API's `respond()` never sends a field the contract lacks, except bodies Better Auth owns (`contracts/auth.ts`), which pin only what the web app reads.
- Changes stay readable across one deploy or rollback: an installed app runs the previous web version for a while after a deploy, and the newer one after a rollback.
- Responses: the web app reads them through `parseResponse` (`apps/web/src/api/parse-response.ts`), which drops keys it does not know, so a response may gain a field in one PR. Response unions are discriminated or their members share no key and each has a required one, and records use string keys, so that `parseResponse` drops only new fields. Anything else an app's version cannot read (a field left out, null or of another type, an enum value or union member it lacks) makes open apps say they do not match the server and reload once into its version (`apps/web/src/app/app-update.ts`), so the schema accepts such a change one PR before the API makes it: a field is removed, renamed or retyped only in a PR after the one that makes it optional and adds any replacement. A new required field still costs that reload after a rollback past it.
- Requests: the API's schemas are strict and a 400 is never read as a version mismatch, so the API accepts a new field (optional) or value one PR before the web app sends it, and drops one only in a PR after the web app stopped sending it; a required field turns optional one PR before the web app stops sending it.
- On the wire: ISO 8601 UTC strings, meters, seconds, bpm, camelCase. Activity paces are never sent; clients derive them from distance and time. A plan carries one pace band per zone and its sessions name zones, never paces.
