# Running Coach: spec

One page max. Phase 1 fills Decisions and Open risks; phase 3 finishes the rest.

## Decisions

- **License:** MIT. Permissive and standard for a public side project.
- **Domain:** the hosting provider's subdomain, no custom domain. Zero cost while there is one user; revisit if a domain is bought.
- **Free tier terms:** a card on file is acceptable if $0 is charged. In the end no chosen provider needs one.
- **History import:** first-time setup imports the user's full Garmin history so PBs cover every run; it runs as a resumable, chunked background job.
- **Hosting:** one Render free web service running a single Docker image (Express serves the built SPA and the API, spawns uvicorn for the Garmin service on localhost, runs the job worker in-process behind an env flag), Neon Free Postgres, GitHub Actions cron as the daily sync trigger. Why: the only layout with no card and enforceable $0 (Render suspends instead of billing, Neon never bills); free tiers do not allow separate workers; one origin keeps session cookies simple.
- **Rejected hosts:** Cloudflare or Vercel for the web app (splits the origin, previews only the web), Cloud Run (billing account, overage), Fly, Koyeb, Railway (card or $1 credit), Render Postgres (expires after 30 days), Oracle Always Free (card, reclaims idle VMs, no subdomain).
- **Cold start:** the service spins down after 15 min idle and wakes in about 60 s; the PWA shell is precached by the service worker and shows a "waking" state until the API answers; in-app polling and the daily cron resume unfinished jobs. Why: unavoidable on free tiers, so design for it.
- **Preview deploys:** Render single-service PR previews (free when the base service is free), selecting a separate Neon staging project through a preview-only env var (mechanism verified in phase 5), with no Garmin or Claude secrets; the URL shows as a GitHub deployment and a one-step Action comments it on the PR. Why: full-stack previews at $0.
- **Login:** Google sign-in only in v1, via Better Auth 1.7 mounted on Express with DB-backed session cookies and database-stored rate limiting; passkeys later as a second method. Why: every email provider needs a verified sender domain we lack; Google works with an onrender.com redirect URI in Testing mode (100 users); Auth.js now points new projects to Better Auth.
- **Origin:** web and API share one origin. onrender.com is on the Public Suffix List, so cookies cannot span subdomains. On iOS installed PWAs, open the Google flow with window.open from the tap so it stays in-app.
- **Garmin library:** garminconnect 0.3.x (Python 3.12+) with its native auth engine; garth is deprecated and unused. Pin exact versions and expect breakage within days of Garmin changes.
- **Garmin tokens:** per-user bundle is `client.dumps()` JSON (di_token, di_refresh_token, di_client_id) stored encrypted; the library refreshes automatically when the access token is under 15 min from expiry.
- **Garmin service state:** stateless for data calls (bundle in, refreshed bundle out, API writes back only when it changed, single-flight per user via a DB lock); the 2FA connect flow is two calls that hold a live session in process memory with a short TTL. Why: the MFA intermediate state is a live HTTP session that cannot be serialized; one container makes in-memory state safe.
- **Garmin politeness:** about 1 s between data calls, up to 1000 activities per page during the history import, per-user client cached for a short TTL to avoid repeated login round trips, never auto-retry 429 (login blocks last about 1 h).
- **Garmin calls:** get_activities, get_activities_by_date, get_activity, get_activity_splits, get_activity_typed_splits, get_activity_details (series + polyline), get_activity_hr_in_timezones, download_activity (ORIGINAL = FIT), get_heart_rate_zones, get_personal_record, upload_running_workout (PaceTarget), upload_strength_workout, update_workout, delete_workout, schedule_workout, unschedule_workout, get_scheduled_workouts, get_devices.
- **Watch baseline:** Instinct 2 Solar on firmware 13.19+ (platform in maintenance mode): step workouts with pace, HR, time, distance or open targets and strength sets reach it via Garmin Connect; it reports HRV status, training readiness, training status and load, VO2 max, wrist running power, Body Battery and sleep; no running dynamics without a pod, no multi-band GPS, 4 to 5 data fields per screen; pushing scheduled workouts overwrites its calendar.
- **Engine boundary:** packages/engine owns every number as pure, tested functions; Claude only selects among engine-validated session templates, writes the text, and proposes deltas the engine accepts or clamps; only the engine writes plan state. Why: plans must be safe and identical for identical inputs.
- **Engine rules (policy constants, cited in code):** paces from Daniels VDOT of the best recent race; weekly volume up at most 10% and no single run over 110% of the 30-day longest (RUNSAFE 2025), down week every 4th; at least 80% of running time easy, at most 2 quality sessions at 3 runs/week, at least 48 h between hard days; long run at most 30% of weekly volume or 150 min; per session T at most 10%, I 8%, R 5% of weekly km; taper 2 weeks (3 for marathon) cutting volume 40 to 60% while keeping intensity; minimum plan length 8 weeks for 5K/10K, 12 half, 18 marathon.
- **Missed and return:** missed runs are dropped, never rescheduled; re-enter at about 70% volume after 7 days off and 50% after 14; after injury or illness a walk-run progression with a day off between runs and +10 to 30% per week until 75 to 80% of prior volume; ACWR is display-only; Riegel exponent 1.06 for predictions, with an added margin for the marathon.
- **Claude model:** default claude-opus-5-5 at effort "low" with structured outputs (output_config.format from the zod schema, thinking display omitted); fallback claude-sonnet-5-5; model is a per-user setting populated from GET /v1/models. Why: about $0.89 per user per month on Opus vs $0.44 on Sonnet for about 19 calls, paid by each user through their own key (the app bears no Claude cost), and plan advice carries injury stakes.
- **Claude plumbing:** no prompt caching or Batch API in v1 (calls are days apart, so cache writes never pay back); validate a new key with GET /v1/models (free, 401 on a bad key); check stop_reason for refusal or max_tokens before zod parsing.
- **ORM:** Drizzle 0.45.x with drizzle-kit: SQL migrations generated and committed, applied programmatically at deploy; raw `sql<T>` for time-series aggregates; stay off the 1.0 RC until stable. Why: schema-diff migrations and a small footprint; Prisma's CLI is in flux and 74 MB.
- **Jobs:** pg-boss 12 on Postgres: sync-user with exclusive policy and singletonKey = userId, deterministic job ids (uuid v5 of user + date) so a double cron fire is a no-op, retryBackoff with jittered delays, import-history as chained chunk jobs writing a cursor row; the worker runs in the API process, with the separate entrypoint kept for local dev.
- **Encryption:** AES-256-GCM via Node crypto, 12-byte random IV, AAD = userId|column|keyVersion, per-purpose subkeys derived with HKDF from one env master key, versioned keys with lazy re-encrypt on read; no libsodium or pgcrypto. pino with redact paths plus a Secret wrapper whose toJSON returns "[redacted]".
- **Web framework:** Vite 8, React 19, React Router 8 in data mode, vite-plugin-pwa with registerType "prompt"; not Next.js. Why: a client-only app gains nothing from Next, and static export drops its server features anyway.
- **Data fetching:** TanStack Query 5 with queryOptions factories and keys [resource, "list", filters] / [resource, "detail", id]; a thin typed fetch wrapper over a zod 4 contract map in packages/shared, response.parse() on the client. Why: ts-rest and zodios are stuck on zod 3; openapi-fetch needs a second toolchain.
- **Charts:** Recharts 3 through shadcn ChartContainer, colors as var(--chart-n), ReferenceLine for targets, animations off, 1 Hz series LTTB-downsampled, chart screens code-split. visx is the exit if bundle or performance budgets fail.
- **UI kit and tokens:** shadcn CLI 4 on Tailwind 4.3; tokens as oklch CSS variables in :root mapped through @theme inline, dark values in :root with no .dark class; defaults removed with `@theme { --color-*: initial; --text-*: initial; --radius-*: initial }` (keep white, black and the --spacing multiplier for shadcn) so only token utilities exist.
- **Map:** react-map-gl 8 (mapbox entry) with mapbox-gl 3, lazy-loaded; the maplibre entry is the exit if Mapbox terms or the 50k free loads per month bite.
- **Lint and format:** ESLint 10 flat config, typescript-eslint 8, Prettier 3 with prettier-plugin-tailwindcss; eslint-plugin-better-tailwindcss 4 with no-unknown-classes, no-conflicting-classes, no-duplicate-classes and no-restricted-classes using the arbitrary-value pattern `-\[[^\]]+\](/\S+)?$`, exempting components/ui/** and data-[...] variants; not Biome (its Tailwind rules are nursery).
- **Boundaries and naming:** eslint-plugin-boundaries 7 with eslint-import-resolver-typescript (web never imports api; engine and shared import no I/O or node built-ins); eslint-plugin-check-file enforces kebab-case for .ts, .tsx and .css files, component identifiers PascalCase; dependency-cruiser only in CI for cycles.
- **Development model:** Claude Code sessions from phase 4 run claude-opus-5-5 at max effort with ultracode multi-agent workflows on; phases 0 to 3 stay on Fable. Why: build quality over token cost.
- **Hooks and toolchain:** lefthook 2 with stage_fixed and parallel for the pre-commit hook; CI runs tsc --noEmit, eslint and prettier --check. Node 24 LTS, pnpm 10, Python 3.12+ with uv, ruff, mypy, pytest.

## Open risks

- Garmin access is unofficial and actively fought: Cloudflare TLS fingerprinting since March 2026, Developer Program is business-only, and logins from datacenter IPs have been blocked. Mitigation: phase 2 also tests one login from a Render instance; the reconnect UX ships in slice 1; a local CLI connect path stays as fallback.
- Refresh-token rotation and lifetimes are unverified, so a refresh race could kill a bundle. Mitigation: single-flight per user, write back only on change, test in spike 3.
- Render free instance size (reported 512 MB and 0.1 CPU, unverified) must hold Node, uvicorn and curl_cffi; 750 instance hours per month are shared with PR previews; GitHub cron is disabled after 60 days without repo activity.
- Losing the master key loses every Garmin bundle and Claude key. Keep an offline copy and test rotation before launch.
- Google OAuth stays in Testing mode (100 hand-added users, "unverified app" screen) until brand verification, which needs a domain; the iOS PWA window.open flow is untested.
- Opus 5.5 thinking tokens cannot be disabled and are outside the cost estimate; plan generation output will exceed 600 tokens.
- Percent-based volume caps collapse at 3 runs per week (30% of 40 km is a 12 km long run); thresholds are population-study constants, not safe lines. Surface conflicts with marathon goals instead of bending silently.
- Recharts 3 is 151 KB gzipped with a redux dependency; 3,600-point series stutter on phones without downsampling.
- Drizzle 1.0 RC changes the migration layout; pg-boss has one maintainer and frequent releases. Pin exact versions.
- Pushing scheduled workouts overwrites the watch calendar, including an existing Runna schedule.
- Arbitrary Tailwind values cannot be disabled in the engine, so that ban is a regex; no-unknown-classes catching palette classes after `--color-*: initial` is untested until bootstrap.
- Render preview env-var override, Node 24 as the LTS line and the IS_PULL_REQUEST-style preview detection are to be verified in phase 5, not from memory.
